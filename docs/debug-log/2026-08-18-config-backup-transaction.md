# 配置备份安全与导入事务（2026-08-18）

## 第一轮：导出仍可写出明文凭证

### 现象

`ConfigBackupService.exportToFile` 虽默认排除凭证，却保留 `includeCredentials=true`；开发者页主动提供该选项，
README 和界面文案也把明文密钥导出描述为受支持能力。设备 ID 同时被当作 Gateway Bearer 使用，却会随备份导出。

### 假设·判断原因

“默认安全”仍允许一次误点生成完整明文密钥文件，不符合项目“配置导出须排除密钥字段”的边界。
`billing_device_id` 既是本机身份又是鉴权值，同样不应迁移。

### 措施

删除 `includeCredentials` 参数与 UI 选项；导出永久过滤凭证、license、token 和本机标识；同步中英文界面、
README 与生成的本地化代码。云账户导出的旧提示也改为明确“不含凭证值”。

### 验证结果

行为测试覆盖现有凭证命名和本机字段。变异探针移除凭证过滤后，导出文件检查立即失败。

### 复盘

敏感导出不能依赖默认值或确认框，而应在服务边界永久禁止。文案也属于安全契约，不能与实现相反。

## 第二轮：坏备份与写失败留下半恢复状态

### 现象

导入循环边校验边写入：后置条目类型错误时，前面条目已经生效；平台写入中途失败也没有回滚。
`cloud_accounts` 只要外层是 String 就能写入，账户 reload 会吞掉内部 JSON 错误并留下空运行时列表。

### 假设·判断原因

SharedPreferences 没有事务，且 setter 先更新内存缓存再等待平台写入。要保持一致性，必须在第一笔写之前完成
格式与业务结构校验，并显式保存旧值用于逆序补偿。

### 措施

ConfigBackupService 先解析完整备份、检查版本和五种允许类型，并校验云账户持久化结构；ConfigService 提供
受控快照和批量恢复，检查每次写入结果，失败时逆序恢复旧值或删除原先不存在的 key，最后统一刷新内存缓存。

### 验证结果

测试覆盖五种类型、后置坏条目、未来版本、损坏云账户结构与第二笔平台写失败。移除云账户校验或旧值写回的
变异探针均使对应测试失败；定向 ConfigBackup/CloudAccount 测试通过。

### 复盘

“先完整验证，再开始写”只解决输入错误；真实持久化仍会失败，因此还需要旧值快照与补偿。批量偏好读写应由
ConfigService 维护，ConfigBackupService 只负责备份格式和安全过滤。

## 第三轮：成功提示跨层且语义相反

### 现象

`BackupResult.message` 在 Service 层硬编码中文和“已恢复”；导出路径也复用它，中文界面显示“已导出：已恢复”，
英文界面还会混入中文。

### 假设·判断原因

导入、导出共用一个结果对象，但把面向用户的动作词提前固化在 Service 层，调用方无法按动作和语言正确表达。

### 措施

结果对象只保留结构化计数；两处 UI 将设置数和凭证数传给 l10n，由导出/导入各自的本地化模板生成提示。

### 验证结果

重新生成 l10n 后，两处 UI、服务和定向测试通过静态分析与编译。

### 复盘

Service 只返回结构化数据；动作语义和自然语言留在 UI 本地化层。共享结果类型不应携带某一个调用场景的文案。
